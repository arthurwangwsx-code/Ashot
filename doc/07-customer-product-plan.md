## 1. 产品目标与范围

把 Ashot 从可用的个人截图工具升级为可由普通用户自行安装、授权、截图、编辑、导出、恢复和升级的 macOS 产品。GitHub 继续承担源码与安装包分发；用户使用截图功能不需要 GitHub 账号、Token 或开发工具，截图也不因使用 GitHub 分发而上传到 GitHub。

对标 Shottr 的任务效率、轻量菜单栏形态、预览/编辑切换和细节可靠性，不复刻其品牌、素材或完整商业功能集合。维持本机截图、本机 OCR、本地存储；首版不引入账号、收费系统、云端图库、AI 服务或多人协作。

保留现有 SwiftUI + AppKit + ScreenCaptureKit 技术栈，逐步抽取可测试的服务与数据模型，不做全量重写。

产品完成标准是“用户能独立完成任务且不会丢图、误导或泄露”，不是“菜单已经有该功能”。当前已有但不完整的能力必须进入明确的完善批次，不能用永久隐藏代替完成；验收前可以标注实验性，不能作为稳定功能宣传。

## 2. 已确认差距与复核依据

以下是源码层面的发现；未特别注明的场景尚未在真实 GUI 中复现。

| 编号 | 当前实现/差距 | 用户影响 | 定位 |
| --- | --- | --- | --- |
| UX-01 | 启动直接调用系统屏幕权限申请，拒绝后用模态警告恢复；没有完整 onboarding 和待恢复动作 | 用户不知道为何授权、返回后怎样继续，也可能误以为应用没启动 | `AppDelegate.swift`；`Services/ScreenCapturePermission.swift` |

| OC-01 | 编辑器 OCR 输入为原图；OCR 和二维码检测从同一点击并发启动并修改相同结果状态，二维码还直接写剪贴板 | 遮挡后的内容可能被原图 OCR 再次读出；结果与剪贴板可能受回调顺序影响 | `EditorViewModel.swift:318-355`；`CanvasView.swift` 的 `.ocr` 分支 |

## 3. 首次安装与权限设计

### 3.1 首次运行流程

安装位置检查 → 简短欢迎页 → 用户点击“开始第一次截图” → 权限解释及系统申请 → 返回后验证状态 → 用户点击“继续截图” → 第一张结果 → 学习复制/编辑/保存。

欢迎页提供“开始截图”和“用示例图片体验编辑”；后者无需屏幕录制权限。介绍应用位于菜单栏，并提供再次打开主窗口/最近截图的入口，避免菜单栏拥挤时用户找不到应用。

优先引导将应用装入 `/Applications` 或明确选择的稳定、可写安装位置。对于 DMG、只读或临时位置运行，先说明迁移原因；不在未经确认时覆盖已有版本、退出其他实例或删除其他副本。

### 3.2 按能力、按时机申请

| 能力 | 申请时机与降级 |
| --- | --- |
| 屏幕录制 | 用户首次明确开始捕获时申请。拒绝后仍可编辑已有图片和访问设置 |
| 辅助功能 | 首次开启自动滚动/跨应用事件能力时单独解释和申请；普通截图不应以此为前提，手动滚动保留可点击停止 |
| 文件位置 | 首次保存或选择自动保存位置时使用系统文件/目录面板；按实际需要保存访问凭据，不要求全盘访问 |
| 登录时启动 | onboarding 结束后可选设置，默认不打开；需反映系统实际状态 |
| 诊断、通知 | 默认采用应用内状态反馈；诊断上传独立同意，不为了“截图已保存”额外申请通知权限 |

解释文案示例：“Ashot 需要读取屏幕内容来截取你选择的区域。它只在你启动截图时工作；截图与文字识别在本机处理。”最终文案必须与实现及后续网络能力一致。

### 3.3 权限恢复模型

PermissionCoordinator 对外区分产品流程状态：未完成设置、申请中、待用户在系统设置处理、重新检查、可捕获、暂不可用、恢复建议。不能把这些全部当成系统精确返回的授权枚举。

`CGPreflightScreenCaptureAccess()` 等布尔查询不能独立区分“从未询问”“明确拒绝”“受设备管理限制”。结合本应用申请历史、系统查询和实际捕获错误提供合适提示；不能只因返回 false 就断言被企业策略禁止，也不能只因以前点过允许就显示可用。

系统设置切回应用时自动更新状态，但不悄悄执行遗留截图。只保留短时有效的动作意图，由“继续截图”重新进入选择；应用重启、目标关闭或会话过期时重新确认目标。申请/警告去重，防止连按快捷键造成弹窗叠加。

跳转系统设置失败时提供可读路径。只有在重新检查仍不可用且证据支持时才建议退出重开；重启前保留编辑草稿。不读取/改写 TCC 数据库，不宣称可以消除系统自身的再次确认提示。正式版固定 Bundle ID 和签名身份，开发测试身份与正式版隔离。

系统 ScreenCaptureKit 选择器可作为兼容性或显式目标授权方案进行专项验证，但不直接假定它能替代所有高频自定义区域截图流程。

## 4. 页面与交互体系

### 4.1 应用结构

不建立常驻的大型首页。保留六类必要界面：首次使用/恢复窗口、菜单栏菜单、截图选区层、浮动预览、编辑器、设置与历史。

菜单分为捕获、最近结果与导入、设置与帮助。提供“重新打开最近截图”“从文件打开”“从剪贴板新建”“检查更新”。再次启动已运行应用应聚焦已有实例/窗口，不再运行第二套热键与权限逻辑。

### 4.2 截图选择

区域支持尺寸反馈、调整后确认、Esc 取消、Shift 比例约束；Space 用于切换可视窗口选择，显示悬停高亮并由点击确认。现有快捷键可保留并提供迁移说明，不静默抢占系统键位。

全屏明确是鼠标所在显示器、当前显示器还是选择的显示器，不在文案与实现间混用“主屏”。预览、编辑器与钉图优先出现在捕获来源屏幕/当前 Space；显示器拔出时安全重定位。

“重复上次区域”保存显示器标识、逻辑区域及屏幕配置快照；布局变化后重新选择，不盲目套用旧坐标。延时截图显示可取消倒计时，不阻塞主线程；取消不产生历史、剪贴板或保存副作用。

隐藏桌面图标改为捕获过滤/合成方案的可行性验证，不再通过重启 Finder 达成。若暂时无法达到像素效果，明确说明实验状态与限制，而不是继续改变用户桌面全局设置。

### 4.3 截图后的默认体验

第一张完成时介绍“轻量预览”和“直接编辑”两种路径，并记住选择。默认轻量预览不强抢焦点；编辑动作才激活编辑器。预览主要显示复制、编辑、保存，OCR、钉图等置于次级动作。

自动关闭可配置为 5 秒、10 秒、保持显示；悬停、键盘操作、保存对话框和 OCR 工作中暂停。连续截图使用有界最近队列，上一张始终可恢复；未完成操作不能被新图无提示替换。拖出预览/编辑器可向 Finder 或支持图片文件的应用交付文件，临时文件清理不得早于拖放消费者使用结束。

复制/保存成功用短暂、非模态反馈；失败保留图片和当前编辑，提供重试/选择其他位置，不能吞错后关闭。

### 4.4 编辑器与设置

编辑器采用主工具条、画布、上下文属性区和稳定的复制/保存出口。先展示常用工具，高级工具渐进展开。属性区反映当前选中对象；没有对象时修改下一次绘制的默认样式，避免两者混淆。

明确关闭窗口、退出应用、复制成功后隐藏、保存草稿的不同语义。默认提供最近会话恢复；持久草稿受历史/隐私偏好控制。未保存修改不能静默丢弃。

设置用可伸缩侧栏或分组导航组织：通用、截图与预览、快捷键、保存与历史、权限与隐私、更新与关于。不是把现有设置继续塞入固定小窗口。所有开关必须能即时生效或清楚说明生效条件。

统一中文/英文提示、错误码到本地化文案的映射、按钮焦点、工具提示、VoiceOver 标签、对比度、深浅色、减少动态效果和键盘导航。视觉验收需使用真实应用截图，不能仅凭源码判断已经舒适。

## 5. 不完整功能的完成定义

### 5.1 编辑事务与渲染（先处理数据损失）

建立 CaptureDocument：原图、像素尺寸、逻辑尺寸、颜色空间、标注/图片图层、裁剪状态、草稿和导出状态。CommandHistory 或 UndoManager 记录添加、删除、复制、移动、缩放、改样式、改文本、裁剪、美化和插入图片。

一次拖动只形成一次可撤销操作；新编辑清空 redo 分支；撤销恢复对象顺序与原位置。粘贴图片成为独立图层，裁剪以非破坏方式记录可见区域，不清空标注。需要不可逆栅格化时提供单独命令并清晰确认。

CanvasRenderer 作为画布与导出共享的渲染核心；把显示缩放与实际导出分辨率分离。选区裁剪、Retina 1x/2x、透明度、JPEG 背景色、颜色空间和长图应具有独立测试样本。

### 5.2 统一保存、复制和拖放

所有入口使用一个 ExportService 和同一份导出选项：PNG/JPEG/TIFF、像素倍率、JPEG 质量与透明背景处理、位置和命名规则。

自动保存使用可靠的文件名占用/排他创建策略，不能仅依赖“先检查文件是否存在再写入”。磁盘满、目录删除、网络盘离线、只读路径、编码失败必须可恢复。剪贴板/文件结果和 UI 成功状态绑定到同一个不可变渲染快照。

### 5.3 真实滚动长截图

流程：选择滚动区域 → 确认自动或手动模式 → 缓存稳定目标/显示器 → 按内容稳定性采帧 → 实时长度及进度 → 完成/保留部分/重试 → 统一截图完成流程。

自动滚动必须绑定明确目标，权限撤销、用户主动干预、窗口关闭或焦点变化时停止，不把事件发送给其他应用。手动滚动是完整可用的替代路径，不因辅助功能未授权而失去停止按钮。

拼接处理重复帧、固定页头/页尾、横向漂移、自然滚动方向、懒加载、动态内容和无可靠重叠。低置信度时允许用户重试或调整接缝，不静默生成缺行结果。空白/高度重复页面应承认匹配不确定，不宣称任意 App 都能完美拼接。

采样与拼接移出主线程，采用降采样匹配、分块处理和内存/输出尺寸预算。原图预算、解码缓冲、匹配缓存及最终图分开计量；保留可取消工作流。超限须明确告知“达到最大长度，保留了部分结果”，不能仅返回首帧并当作成功。

首批验收包含 Safari、Chrome、一个真实 Electron 滚动容器和原生滚动视图，逐项公布支持范围；复杂/无限滚动场景只承诺明确的部分结果与恢复能力。

### 5.4 历史、草稿与隐私

建议首次使用明确选择“仅保留当前会话（默认）”或“开启本地历史”。升级已有用户时保留设置和已有图片，不静默删除，补充说明即可。开启历史后按天数、数量、磁盘容量限制保留，展示实际占用，允许暂停、搜索、批量清理和导出；历史缩略图按需加载。

内部索引与图片归属必须固定到存储仓库。切换自定义目录使用显式迁移事务：校验新位置 → 用户选择迁移或另建库 → 验证拷贝与索引 → 原子切换 → 失败回滚。清理默认只处理本应用管理的文件，不删除目录中其他文件。

增加“敏感截图”模式：捕获前启用，不自动复制原图、不保存原图历史；用户完成处理并主动导出才写入结果。提供明确的实色遮盖工具，导出只包含最终像素，不携带可恢复原图、图层或隐藏 OCR 文本。模糊/像素化不能描述为安全擦除。

在普通模式下，遮盖后提醒“原始截图可能仍在本地历史或已有剪贴板副本中”；可以清理本应用管理的对应数据，但不得保证清除系统/第三方剪贴板历史、备份或实现磁盘级安全擦除。已有截图不要因升级自动更改保留策略。

### 5.5 OCR、二维码与其余已有工具

OCR 默认识别当前可见渲染结果或明确选区，而不是无提示地绕过遮挡识别原图。提供中英文/自动语言、保留或合并换行、复制预览、进度、取消、空结果和失败区分。每个任务使用 ID 丢弃过期回调。

二维码与 OCR 的任务和结果分离；除用户选择的快速复制动作外，不擅自抢写剪贴板；检测出的链接不自动打开。

钉图补齐缩放、透明度、来源屏幕位置、重新编辑和关闭所有，限制残留窗口及内存。取色统一 HEX/RGB/HSL/OKLCH 配置和复制反馈。背景美化进入文档事务与统一导出，不能成为无法撤销的旁路。标尺清晰区分屏幕逻辑点与图像像素。

## 6. GitHub 分发与应用内更新

### 6.1 安装信任

面向客户的稳定发布必须以 Developer ID Application 签名、Hardened Runtime、Apple 公证和 stapling 为发布门槛。签名私钥、Sparkle 私钥和公证凭据留在受控钥匙串，不进入仓库/客户端。

在干净用户环境通过浏览器下载真实 Release，再验证首次安装、正常打开、离线启动、权限申请和更新。不能用本机开发构建成功或手动去除 quarantine 代替客户安装验收，不要求客户禁用 Gatekeeper。

当前预览版没有 updater，因此升级到第一版带 updater 的受信任产品需要一次手动安装引导。不能承诺现有预览包可以凭空自动更新。保留原有数据；签名变化后的权限状态要重新验证。

### 6.2 推荐 Sparkle 更新

使用 Sparkle 2 的受支持稳定版本，不自行编写下载并覆盖 `.app` 的安装器。GitHub Releases 保存版本化二进制；同仓库的 GitHub Pages 承载稳定的更新 feed，feed 引用具体版本附件。Pages 是方案依赖，当前未启用，不代表已经可用。

使用 HTTPS 与 EdDSA 更新签名，正式签名一起校验；评估启用提取前验证与签名 feed。stable/beta 两个更新通道，默认 stable，用户主动加入 beta。没有 GitHub 登录要求，不在客户端放发布 Token。

用户可手动检查更新；后台检查/下载选项透明可控。安装前处理未保存文档，失败保留当前可用版本。网络离线、GitHub 不可达、旧系统无可用新版本应有正常状态，不能反复打断截图。紧急修复使用更高版本号前向发布，不把不安全降级当作常规回滚策略。

### 6.3 发布管线增强

在现有脚本上增加：显式单调递增构建号（跨分支校验，而非仅 Git 提交计数）、稳定/测试通道、官方签名与公证校验、发布前后回下载校验、更新 feed 签名与发布、断点恢复、已上传资产 SHA 校验和发布完成记录。

顺序：锁定已审核提交 → 全套验证 → 构建/签名/公证 → 生成包及签名 → 草稿附件完整性检查 → 发布 Release → 最后更新 feed。失败不得先更新 feed；恢复必须复用已核验产物，不覆盖已公开的同版本附件。

公开仓库自动 CI 可以运行无需私钥的静态检查、单测与构建；个人 Mac 的签名发布只接受受信任的已审核提交，不把未受信任 PR 直接交给持有签名私钥的自托管 runner。

首个对客版本还需明确源码许可证、第三方声明、隐私说明、反馈入口和系统兼容声明。收费/激活并不是本轮产品化的必要前提。

## 7. 最小架构调整

| 模块 | 责任与验证边界 |
| --- | --- |
| AppCoordinator / WindowCoordinator | onboarding、单实例、菜单和窗口生命周期、焦点/Space/屏幕定位 |
| PermissionCoordinator | 按需授权、状态重新检测、去重、恢复动作；通过接口模拟状态，真实系统弹窗单独验收 |
| CaptureSession / CapturePipeline | 普通/窗口/延时/滚动统一结果、取消及错误；来源、坐标、缩放和会话快照 |
| CaptureDocument / CommandHistory | 可编辑文档、图层、裁剪和事务撤销；纯逻辑与渲染 golden tests |
| ExportService / HistoryStore | 输出格式、原子写入、存储隔离、迁移、保留策略与隐私边界 |
| UpdateService / Diagnostics | Sparkle 适配、更新前文档处理、最小化且可预览的诊断包 |

不要把这些全部扩成独立框架或微服务。先给现有单例增加可注入边界，覆盖回归，再逐个迁移调用点。UI 线程只负责事件与呈现，图像编码、匹配和磁盘处理走有界后台任务。

## 8. 分批交付及发布门槛

| 批次 | 交付范围 | 完成证据 |
| --- | --- | --- |
| A：产品契约与基线 | 确认默认隐私/预览行为、窗口/快捷键语义、兼容目标；补数据损失复现用例 | 状态流与验收矩阵清楚；失败用例可重复；测得性能基线 |
| B：安装授权与捕获 | onboarding、按需权限/恢复、实例与路径、目标选择、重复区域、可取消延时、预览队列 | 新用户独立完成截图；拒绝后恢复；多屏与焦点不乱；取消无副作用 |
| C：编辑/导出/隐私 | 完整撤销、无损裁剪/贴图、统一渲染保存、历史迁移、敏感截图、OCR 状态隔离 | 数据损失用例全部修复；导出像素和格式一致；敏感流程不产生原图持久副本 |
| D：现有高级能力完善 | 指定区域长截图、自动/手动模式、拼接进度和恢复、钉图/取色/美化 | 支持矩阵逐项通过；低置信度、超限与失败不会伪装成功 |
| E：对客候选版 | 真实公证分发、Sparkle 更新、兼容版本、可访问性、诊断/反馈和完整回归 | 干净安装与 N→N+1 更新通过；无阻断缺陷，实际发布包与证据可追溯 |

实施顺序总体串行，基础回归与测试样本随每批一起补充。证书/公证和最低系统版本的可行性在 A 批就验证，不能到 E 批才发现根本阻塞。每批独立审查、提交、验证，不用一次大提交掩盖风险。

完成 B+C 可交付可靠日常截图 beta；D 未通过时不得把长截图说成稳定功能。正式 `1.0` 候选版以本范围既有功能全部完成验收为目标，不以日期代替门槛。

当前最低 macOS 为 26.2。建议把 macOS 14+ 作为兼容可行性候选：先审计 API、尝试编译，再准备实际系统测试；不能只改 deployment target 就宣布支持。若维护成本过高，明确更窄范围。Universal 只代表两种架构编译成功，Intel 支持仍需对应运行证据。

## 9. 验收矩阵与可测目标

| 类别 | 必测场景 |
| --- | --- |
| 安装 | 浏览器下载、DMG 安装、重复副本、只读位置、干净用户、首次离线启动；不更改系统全局安全策略 |
| 权限 | 未申请、拒绝、系统设置返回、撤销、签名/路径变化、系统升级后再次检查、连续触发、多次拒绝、受管理设备的可解释失败 |
| 捕获 | 区域/窗口/全屏/延时/重复区域/长图；Esc 取消；捕获中显示器拔出、锁屏/唤醒、全屏 Space、混合 DPI |
| 编辑 | 删除→撤销、拖动→撤销、改字→撤销、裁剪→撤销、贴图→撤销、撤销后新操作、多个文档与输入法组合 |
| 导出/隐私 | 不同入口格式与尺寸一致；大图、透明 JPEG、磁盘满、只读目录、改目录、并发同名；遮盖后 OCR 与导出；关闭历史/敏感截图不写原图 |
| 长截图 | 固定头尾、重复行、懒加载、横向偏移、反向滚动、动态内容、低置信度、达到预算、自动事件目标变化、部分结果保留 |
| 更新 | stable/beta 隔离、N→N+1、离线、坏包/错误签名、只读安装位置、未保存编辑、旧系统无兼容版本、权限与历史保留 |
| 体验/稳定性 | 中文/英文、长文本、VoiceOver、纯键盘、深浅色、减少动画；反复截图/钉图/编辑并释放内存，长期空闲无采帧 |

以下为建议的目标，不是已经达到的指标：在选定的 M1 Pro、4K 屏幕和固定截图设置下，排除系统授权与冷启动，预热后至少采样 100 次；选区层出现 P95 ≤200ms，用户确认到可预览/复制 P95 ≤500ms。首次安装观察 5 名新用户，至少 4 名无需开发者帮助完成安装后的第一张截图；记录实际耗时与失败点，不把小样本当总体成功率。

主流程必须零已知数据损失/错误泄露/未解释保存失败。性能、内存和长图预算先做基线再定最终门槛；增加系统和显示器组合后分别记录，不把单机成功外推到所有 Mac。

建议新增测试组：PermissionFlowTests、EditorCommandTests、ExportConsistencyTests、HistoryMigrationTests、SensitiveCaptureTests、ScrollingStitcherTests、UpdateFeedTests，以及可重复的 GUI 冒烟脚本。UI 自动化不能绕过系统安全控制来“证明”权限流程。

## 10. 实施默认值与外部发布条件

本轮按推荐默认值实施：轻量预览；新用户默认仅当前会话，持久历史显式开启，既有用户保持原设置；常规模式自动复制提供显式偏好，敏感模式关闭自动复制；普通截图不要求辅助功能；稳定版才进入默认更新通道；不加入登录、收费和云存储。

源码许可证不代为授予；最低系统支持必须以实际验证为准；Developer ID、公证和更新签名凭据未就绪时，交付代码与本机测试包，但不得发布或标记为已公证正式版。既有历史不做静默迁移或删除。
