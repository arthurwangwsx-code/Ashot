# 验证与维护

## 1. 验证分层

### 1.1 纯逻辑和单元测试

运行：

```sh
./dev.sh test
```

当前测试覆盖：

- 快捷键编码、默认值、系统保留组合、冲突相关纯逻辑和禁用持久化语义。
- 中英文语言选择。
- 图片格式编码和避免覆盖的文件命名。
- 截图模式来源、截图后设置默认值和独立开关。
- 三指拖动缺少 `mouseDown` 时的选区起点回退。
- 区域遮罩的 Space/Esc 键盘动作映射。
- 选区有限值、显示器裁剪和最大输出像素防护。
- ScreenCaptureKit source rectangle 到 AppKit 全局坐标的转换。
- 预览在右、左、下方换位和全屏光标回退。
- 编辑器标注几何、直线命中、像素化区域和 Shift 约束。
- 编辑工具默认字母的完整性、唯一性、输入合法性和显式禁用语义。

单元测试不覆盖系统权限弹窗、真实全局快捷键、ScreenCaptureKit 输出、触控板手势或视觉位置。

### 1.2 编译与签名构建

```sh
./dev.sh check
./dev.sh build
```

- `check`：无签名 Debug 编译，适合快速发现类型和 API availability 问题。
- `build`：生成签名的 `build/Ashot.app`，用于真实权限和交互验收。

签名验证：

```sh
codesign --verify --deep --strict --verbose=2 build/Ashot.app
```

### 1.3 真实 macOS 验收

签名构建成功仍不能替代真实截图。必须在目标 Mac 上使用已授权的应用进行下面的视觉与行为检查。

自动化冒烟验收可以用 `--capture-area` 启动参数直接打开真实区域遮罩，避免依赖开发机上用户自定义的全局快捷键；该参数只用于本地验证，不是产品菜单能力。

## 2. 预览定位回归矩阵

| 场景 | 预期结果 |
| --- | --- |
| 屏幕中部小选区 | 预览优先出现在选区右侧，不重叠 |
| 靠近右边缘选区 | 预览切换到左侧 |
| 横向占满、上下有空间 | 预览切换到下方，空间不足再到上方 |
| 接近全屏的选区 | 预览靠近当前光标，并保持在 visible frame 内 |
| 全屏/延时截图 | 使用光标回退，不固定在屏幕右下角 |
| 副显示器选区 | 预览留在该副显示器，不跳回主屏 |
| 负 X 或负 Y 布局 | 位置仍贴近选区，不能被错误钳制到主屏坐标 |
| Dock 在左、右或下方 | 预览不覆盖 Dock，边距基于 visible frame |
| 菜单栏所在屏幕 | 预览不越过可见顶部 |

## 3. 普通截图回归清单

### 3.1 区域截图

- 普通鼠标拖动可以选择。
- 开启 macOS 三指拖移后，三指拖动可以直接建立选区。
- 松手后截图区域与遮罩框一致。
- 小于等于 3 点的误操作不产生截图。
- Esc 正常取消。
- 未拖动时按 Space，遮罩立即消失并截取原来位于最前方的非 Ashot 窗口。
- 连续触发两次区域截图，只保留最后一个遮罩会话，Esc/Space 不重复回调。
- 将指针停留和拖动一段时间，尺寸与坐标提示持续刷新且应用不退出。
- 多显示器分别检查 Retina 比例和坐标。

### 3.2 截图后操作

- 预览开、复制开：松手后可以立即粘贴，预览随后出现。
- 预览关、复制开：不弹预览，但剪贴板可用。
- 预览开、复制关：弹预览，但不会覆盖已有剪贴板。
- 自动保存开：文件后台写入指定目录，格式和扩展名一致。
- 自动保存失败：预览和历史仍可用，并显示限定范围的错误。
- 连续快速截图：旧预览被替换，不出现多个缩略图窗口。

### 3.3 预览工具

- 编辑、复制、保存、OCR、钉图和关闭动作都操作当前图片。
- 悬停超过 6 秒不会自动关闭，离开后恢复计时。
- 手动拖动预览正常。
- 保存失败后预览不应被意外关闭。

### 3.4 编辑器工具与快捷键

- 设置 → 快捷键同时显示“截图快捷键”和“编辑工具快捷键”，两个恢复按钮互不影响。
- 编辑快捷键只能录制一个 A 到 Z 字母；数字、组合键和重复字母均被拒绝。
- 禁用一项后重启应用，该工具不应重新获得默认键。
- 编辑窗口中按 `A/R/T` 分别切换箭头、矩形和文本；工具提示显示当前自定义键位。
- 文本工具创建输入框后，输入 `A/R/T` 必须进入正文，不能切换工具。
- 多个编辑窗口同时打开时，字母只影响当前接收事件的窗口。
- 箭头和直线按住 Shift 后吸附到 45°；矩形和椭圆约束为正方形或正圆。
- 直线、像素化在画布预览与复制/保存后的最终图片中均可见。
- 模糊和像素化只作为视觉遮挡验收，不宣称不可逆安全擦除。

## 4. 权限与构建回归

- 全新安装：出现屏幕录制权限请求。
- 拒绝权限：下一次截图显示恢复入口。
- 在系统设置授权后：返回应用并刷新状态，必要时重启一次。
- 同一 Bundle Identifier、签名团队和稳定应用路径的重复构建：检查权限是否沿用。
- 更换签名身份、Bundle Identifier 或应用路径：按可能触发重新授权处理，不能归因成截图代码错误。
- 设置页必须能从菜单栏和 `⌘,` 打开。

## 5. 文档与源码同步检查

每次修改截图链路时检查：

1. `CaptureService` 是否仍保证复制和预览先于编码写盘。
2. 新截图模式是否提供正确的预览锚点。
3. 坐标是否明确属于 View 局部、ScreenCaptureKit display 局部或 AppKit 全局。
4. 新设置是否有默认值、持久化键和中英文文案。
5. 后台任务是否只持有不可变值。
6. 错误提示是否准确描述失败范围。
7. 功能、交互、架构和验证文档是否同步更新。

## 6. 崩溃诊断基线

排查应用自行退出时，先读取 `~/Library/Logs/DiagnosticReports/Ashot-*.ips`，按异常原因和第一个 Ashot 符号聚类，不把权限拒绝误判为崩溃。

2026-08-02 留存的 9 份报告均为相同问题：区域遮罩在 `drawDimensions` 或 `drawMagnifier` 中构造文字属性时，CoreText 收到空字体对象并抛出 `NSInvalidArgumentException`。当前实现只在字体完成可选桥接后写入属性字典，失败时使用无显式字体的系统回退；该问题需要通过长时间移动、拖动和重复区域截图做真实回归。
